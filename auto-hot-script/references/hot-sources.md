# 全域热点源与采集方法

> 本文件只解决一个问题：**在 72 小时窗口内，把「现在大家都在讨论什么」捞全，并且证明它是新的。**

## 一、采集工具的选择

| 场景 | 用什么 | 说明 |
|---|---|---|
| 没有具体 URL，要「现在的热点」 | Agent 原生检索（带时间过滤） | 主力。带 `d2` / `d3` 时效过滤，直接拿到近三天内容，且返回结果自带信源标注 |
| 已知榜单页 URL，静态 HTML | 抓取页面 | 辅助。用于拿榜单排名与热度值 |
| 两者都不理想（页面靠 JS 渲染、要登录） | 浏览器自动化 | 兜底，成本最高，非必要不用 |

**优先检索。** 榜单页好看但只给一个平台，检索能一次覆盖四层，且能顺带拿到报道量——而报道量才是「关注度高」的真实证据。

## 二、四个圈层与检索式

### 1. 社交热搜（用户当下在聊什么）

- 检索式：`微博热搜榜 今日`、`微博热搜 盘点`、`抖音热榜 今天`、`小红书 热门话题 本周`
- 抓取：`https://tophub.today/n/KqndgxeLl9`（微博热搜榜，页面按小时给出上榜快讯与热度值）
- 要点：榜单页的**热度值**（12 万 / 163 万）是可比信号；快讯时间戳（如 `18:30`）可直接用于时效核验。

### 2. 资讯门户（媒体在推什么）

- 检索式：`百度风云榜 实时热点`、`今日头条 热榜`、`腾讯新闻 热点 排行`
- 抓取：`https://top.baidu.com/board?tab=realtime`（服务端渲染，可直接抓）
- 要点：这一层筛掉纯娱乐噪音，也是「非娱乐类至少 2 条」的主要来源。

### 3. 内容平台（长内容在讨论什么）

- 检索式：`B站 热门 排行`、`知乎热榜 今日`
- 要点：这两层的热点通常**延展性最好**——有长文、有讨论、有第二层信息，适合支撑 5 分钟以上的稿子。但要警惕它们比热搜慢半拍，注意核验是不是 72 小时内的新话题。

### 4. 日历与民生（不用搜也知道会热）

- 检索式：`<当前日期> 假期 出行 数据`、`<节气> 养生 讲究`、`<赛事名称> 结果`、`开学 / 考试 / 供暖 / 电价`
- 要点：这一层**可预测**，选题命中率最高，也最容易被忽略。做稿前先过一遍日历：节假日、节气、赛事、开学考试、季节性疾病、物价与政策节点。

> 各平台的榜单页地址与栏目 id 会变。抓不到就退回检索式，不要在死链上反复重试。

## 三、时效核验（三级判定）

| 能确认的 | 处理 |
|---|---|
| 上榜快讯时间戳 / 首发报道时间在 72 小时内 | **入选**，记录时间 |
| 只能确认「最近一周」 | **降权**（时效分记 3 以下）并显式标注 |
| 确认不了时间 | **丢弃** |

三种核验手段，任一条成立即可：

1. 榜单页的上榜快讯时间戳；
2. 最早一篇报道的发布时间；
3. 话题页「24 小时」维度的讨论量是否非零。

**不许用「感觉很新」代替核验。** 老热点翻红与真热点，稿子写法不同，混淆会直接翻车。

## 四、热度信号怎么读

| 信号 | 强 | 弱 |
|---|---|---|
| 榜单排名 | 前 10 | 20 名开外 |
| 热度值 | 百万级 | 十万级 |
| 跟进媒体 | 有央媒 / 门户跟进 | 只有自媒体转述 |
| 讨论形态 | 有争论、有反转、有当事人回应 | 单向通稿 |

讨论形态是判断**延展性**的关键。一个只有官方通稿、没有民间讨论的话题，很难撑满五分钟。

## 五、候选表字段（每轮采集统一落成这张表）

| 字段 | 说明 |
|---|---|
| 热点名 | 话题原词，不改写 |
| 信源 | 可点开的 URL（≥1 条，优先首发） |
| 最近上榜时间 | 精确到日期，能到小时更好 |
| 热度信号 | 排名 / 热度值 / 跟进媒体数 |
| 一句话事实 | 不带评价，只写发生了什么 |
| 接口 | 能接到用户主题的哪个需求或场景；接不上就写「无」 |

最后一项是给第 2 步打分用的。**写「无」不丢人，硬编一个接口才丢人。**

## 六、雷区清单（第 1 步就跳过去，不要留到打分）

政治与历史争议、自然灾害与伤亡消费、未成年人身份信息、医疗诊断与疗效断言、金融荐股与收益承诺、迷信改运、低俗擦边、地域与性别对立、企业负面未经证实传闻。

踩到任一条，无论热度多高直接弃用，也不要放进候选表——放进去只会诱导后面硬选。
