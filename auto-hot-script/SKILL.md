# 热点口播 · 从热点到能直接念的稿

一句话链路：**问清四件事 → 全域捞 72 小时热点 → 打分选一条 → 电台口播出稿 → 过合规与去 AI 味 → 拆成分段提示词模板。**

## 硬规则（先读，违反即返工）

1. **不编热点。** 每一条热点都必须能点开原始信源。查不到就换一条，不许写「据媒体报道」这类无出处的转述。
2. **不硬转主题。** 热点跟主题接不上就做纯热点稿。硬拽是这类稿件最明显的失败特征。
3. **不碰雷区。** 政治、伤亡灾难消费、未成年人、医疗断言、金融荐股、迷信低俗——再热也弃用，不做例外。
4. **热点会烂。** 榜单热度 48～72 小时衰减，交付时必须标注采集时间。
5. **只写稿，不发稿。** 任何发布、投流、账号动作先问用户。

## 第 0 步 · 收参（一次问完，不要分轮反问）

用选择题一次问完这四项，缺项直接取默认值：

| 项 | 选项 | 默认 |
|---|---|---|
| 主题 | 自由文本（正在做的产品 / 账号方向 / 想推的事） | 必填，没有就先问 |
| 平台 | 抖音 / 视频号 / 小红书 / B站 / 快手 / 播客电台 | 抖音 |
| 时长 | 3 / 5 / 8 / 10 分钟 | 5 分钟 |
| 字数 | 800 / 1200 / 1600 / 2000 | 跟时长算（5 分钟 → 1200 字） |

平台决定限流词口径与语感（见 `references/compliance.md`）。**字数与时长冲突时以时长为准**，按 `references/script-templates.md` 的对照表重算，并把「你要的是 X 字，但 Y 分钟对应 Z 字，取 Z」一句话告诉用户。

## 第 1 步 · 全域捞热点（近 72 小时）

用 Agent 原生检索能力：**检索为主，抓静态榜单为辅**。具体源、检索式与时效核验方法见 `references/hot-sources.md`。

四个圈层都要扫，**候选不少于 8 条**：

| 圈层 | 覆盖 |
|---|---|
| 社交热搜 | 微博热搜、抖音热榜、小红书热门话题 |
| 资讯门户 | 百度风云榜、今日头条、腾讯新闻 |
| 内容平台 | B站热门、知乎热榜 |
| 日历民生 | 法定假日、节气、赛事、开学考试、物价、天气 |

其中**至少 2 条来自非娱乐类**（科技 / 民生 / 财经 / 体育 / 政策），避免整张候选表都是明星八卦。

每条候选落成一行：**热点名 / 信源 URL / 最近上榜时间 / 热度信号 / 一句话事实 / 能接到主题的接口**。

时间门槛按三级处理：能确认 72 小时内 → 入选；只能确认一周内 → 降权并标注；确认不了 → 丢弃。**不许猜时间。**

## 第 2 步 · 打分选一条

六维打分，每维 0–5：

| 维度 | 含义 |
|---|---|
| 主题相关度 ×2 | 能不能自然接到主题——唯一带硬权重的维度 |
| 时效 | ≤24h 记 5，≤48h 记 4，≤72h 记 3 |
| 关注度 | 榜单排名、热度值、跟进媒体数量 |
| 延展性 | 撑不撑得起目标时长，有没有第二层信息 |
| 平台适配 | 该平台用户吃不吃这类话题 |
| 合规安全 | 无雷区记 5，沾边即扣，触碰红线直接出局 |

总分 = 相关度 ×2 + 其余四项相加（满分 30）。输出 **Top3 对比表**，标出选中项，理由一句话。

选完立刻判**连接强度**——这一判定决定后面怎么写，不能跳：

| 强度 | 判据 | 写法 |
|---|---|---|
| **强** | 热点本身就是主题的语境、需求或痛点 | 自然过渡到主题，主题占一半以上篇幅 |
| **弱** | 只有关键词相近，逻辑牵强 | 热点讲完就收，主题只做一次邻接提及，不做展开 |
| **无** | 找不到任何合理接口 | **不硬转**。全文纯热点稿，主题不提或结尾一句带过，交付时明确注明「本次为纯热点稿」 |

**宁可判「无」，不要「弱装强」。**

## 第 3 步 · 出稿

结构固定五块，篇幅按 `references/script-templates.md` 的配比切：

**钩子 → 事实层 → 第二层 → 落点 → 收尾**

电台口播的硬要求：

- **短句**。一句一个意思，不要从句套从句。
- 允许的口语连接词：其实、话说回来、你发现没有、说白了、这么说吧。
- **禁用**：三句以上排比、「首先其次最后」、「在这个 XX 的时代」、口号式收尾、总结性套话（「总而言之」「综上所述」）。
- 数字处理：四位数以上的整数口语化（`85400` → 「八万五千多」），带小数的官方口径保留原数（`8.54 万个`），因为精确度本身就是信息。
- 每 2～3 句留一个换气点，段落之间不硬接。
- 全程第二人称对谈感，像跟一个朋友说话，不像念通稿。

## 第 4 步 · 双道预检（顺序不能换）

### 4.1 合规预检（先做——改词会动字数）

按 `references/compliance.md` 的三张表逐条扫：**违禁词 / 平台限流词 / 营销降级词**。

命中即改，输出三列表：**原词 → 替换 → 位置**。只改表达，不改事实。改完复核字数是否还在目标区间。

### 4.2 去 AI 味

**首选调用本机「去AI味」技能**（`qu-ai-wei`）。未安装则引导用户到技能市场搜索「去AI味」安装；同时按下面 5 条兜底自检，**不阻塞交付**：

1. 有没有三句以上的同构排比？
2. 有没有「不仅…还…」「在…的当下」「赋能 / 闭环 / 抓手」？
3. 每段是不是同一个节奏、同一个长度？
4. 有没有 emoji 分区标题，或「总的来说」这类机械收束？
5. 结尾有没有硬凑的反问「你觉得呢？」

命中任一条就改写，不是删句子了事。

## 第 5 步 · 交付（口播提示词模板）

最终交付一份 Markdown，固定六块：

| 块 | 内容 |
|---|---|
| **A 元信息** | 主题 / 平台 / 选中的热点 / 时长 / 字数 / 连接强度 / 采集时间 |
| **B 打分表** | Top3 对比 + 选中理由 |
| **C 合规改动** | 原词 → 替换 → 位置 |
| **D 分段提示词块** | **主体**，一段一块，字段见下 |
| **E 连读版** | 纯文案，无任何标注，可直接进 TTS |
| **F 备用钩子** | 2 条，供 A/B 测试 |

分段提示词块的固定字段：

```
▍00:00–00:25 · 钩子 · 约 120 字 · 语速偏慢
【口播】可直接念的文案，不出现任何标注符号
【画面】建议画面 / 字幕关键词
【节奏】停顿、重音、情绪变化
```

写完把文件落到工作区并呈现给用户。用户只要文案时，跳过 B、C 的说明，直接给 D + E。

## 边界与禁止事项

- 不编造热点、数据、信源；引用必须给得出来源链接。
- 不代做平台合规终判——各平台规则持续变化，交付时提示「以平台最新规则为准」。
- 不代发稿，不接管账号，不代操作投流。
- 不做灾难、伤亡、未成年人、医疗、荐股类选题，即使数据极好。
- 不写标题党式承诺（「看完你就懂了」「最后一条最关键」）。
- 热点稿有保质期，过期后重新跑第 1 步，不要在旧稿上打补丁。
