# GEO · 让 AI 提到你 + B 端获客

两条线，先分流再执行。

- **C 端线**：让产品/品牌被 AI 搜索引擎（豆包、Kimi、DeepSeek、元宝、秘塔、Perplexity 等）**引用和推荐**。核心逻辑是 AI 的回答大量引用少数高权重站点的公开内容——**在那些站点发高质量内容，就是占住 AI 回答的引用位**。
- **B 端线**：下游是企业客户时，AI 引用位的转化链条太长（决策链长、采购不走搜索推荐），**直接挖到可联系的企业名单并落库**才是短路径。

**输入**：一个主题或产品名称。
**产出**：C 端线 = 引用来源分析 + 发布阵地清单 + 每个阵地的合规 Markdown + 发布引导；B 端线 = 下游地图 + 客户线索清单 + CSV 线索库 + 触达动作。

## 双线路由（第一步必做）

拿到主题/产品后先判定下游买家类型，再进对应线：

| 判定依据 | 结论 |
|---|---|
| 用户明说找客户 / 获客 / 找下游 / 销售线索 / 我的货卖给谁 | **B 端线** |
| 产品性质：工业品、原材料、元器件、设备、代工制造、SaaS、企业服务、咨询、大宗批发 | **B 端线** |
| 产品性质：消费品、餐饮、旅游、本地生活、App、课程内容、个人服务 | **C 端线** |
| 明说 GEO / AI 搜索优化 / 让 AI 提到我 / 品牌占位 | **C 端线** |
| 上下游都吃（如设备既卖给工厂也卖给个人） | 先跑 **B 端线**（线索直接可变现），C 端线作品牌占位补充 |
| 判不出来 | 合并成一轮追问（产品是什么 + 谁掏钱买），不逐个轰炸 |

**B 端线产物会写 CSV，C 端线不写。**

## 触发规则

| 用户意图 | 处理 |
|----------|------|
| 给主题/产品，要做 GEO / AI 搜索优化 | 判定下游 → C 端线五步流水线 |
| 给产品，要找客户 / 获客 / 潜在客户 / 下游买家 | 判定下游 → B 端线客户挖掘流水线 |
| 只问 GEO 是什么 | 仅科普，不展开执行 |
| 只要诊断不要发内容 | C 端线只执行第 1–2 步，输出报告 |

## 核心准则

- **先摸底后动手**：C 端线先看 AI 引擎现在引用谁，再决定在哪发；B 端线先定下游再采集，不凭感觉铺量。
- **可发布性优先**：分析再高的权重，用户无法入驻发布就没有意义；有创作者中心的站点优先。
- **一次问清**：信息收集一次性列出缺失项，至多 1 轮追问。
- **可摘录才可引用**：AI 引用的是清晰的结论句、数据、定义和 FAQ——为被引用而写作。
- **线索可溯源**：每条客户信息标注 `来源·时间·适用范围`，查不到就标「待验证」，不用推测冒充事实。
- **合规是底线**：广告法禁用词、平台规范、医疗/金融红线，全流程检查；只用公开信息，不采隐私数据。

# C 端线 · GEO 五步流水线 + 静态站收尾

适用：下游为个人消费者。产出引用占位内容与发布引导。

## 第 1 步 · 联网检索，收集引用来源（摸底）

默认联网执行（WebSearch / 联网检索工具；需要真实浏览器渲染时用 web-access 技能）：

1. 以**真实用户视角**构造 3–6 个典型问句（问句构造参考 @references/seo-template.md 问句库），例如：
   - 「{产品} 怎么样 / 值得买吗」
   - 「{产品} 和 {竞品} 哪个好」
   - 「{品类} 推荐排行榜」「{产品} 官网/入口」
2. 多引擎多问句检索，收集每条回答的**引用来源**：域名、链接、标题、被引用的上下文片段。
3. 去重汇总为「引用来源清单」：域名 | 出现频次 | 内容类型（问答/测评/百科/资讯/视频）| 权重初判。

> 无法直接访问某 AI 引擎时，改用其公开网页版检索结果或通用搜索结果近似替代，并在报告中注明。

## 第 2 步 · 来源站点分析，优选发布阵地（选阵地）

对引用来源清单逐个分析（平台资料库见 @references/platforms.md，入口存疑时联网验证，不臆造）：

- **主站网址**：给出官网地址。
- **创作者中心**：主站或平台有创作者中心的**优先提供**入口地址。
- **可发布性**：是否开放个人注册发布（开放 / 投稿制 / 邀请制 / 不可发布）。
- **权重**：被 AI 引用频次 × 平台搜索权重 × 领域匹配度。

**产出「发布阵地优先级清单」**：

| 优先级 | 平台 | 主站 | 创作者中心 | 可发布性 | 入选理由 |
|--------|------|------|-----------|----------|----------|

并为每个入选阵地给出**内容输出意见和参考**：检索该站同主题的高热内容，归纳其结构、篇幅、关键词布局、语气风格，作为第 4 步的写作依据。

## 第 3 步 · 按 SEO 模板补充信息（集弹药）

用 @references/seo-template.md 的收集模板，对照用户已给信息，**一次性列出全部缺失项**请用户补充（也接受用户直接丢资料/链接，由本技能联网抓取提取）。关键项：

- 核心关键词与长尾词、竞品对比词
- 目标人群与决策链
- 3–5 个差异化卖点及证据
- 信任背书（资质/销量/案例/口碑）
- 行动号召 CTA（搜什么词、进什么店）
- 合规红线（广告法禁用词、行业限制）

## 第 4 步 · 逐平台产出内容（写弹药）

结合第 2 步的站点风格 + 第 3 步的模板信息，为每个入选阵地输出一份 **Markdown 文档**。写作规范见 @references/writing-guide.md，要点：

- **GEO 可引用结构**：标题含关键词 → 开头 TL;DR 结论 → H2/H3 分节 → 数据与事实（标注来源·时间）→ FAQ 收尾。
- **一稿多版**：同一素材按平台风格改写（知乎理性长文 / 百家号资讯科普 / 小红书口语短文 / CSDN 技术教程），不逐字复制。
- **合规自查**：无广告法禁用词、软广如实标注「广告/利益相关」、不碰医疗/金融结论红线。
- 每份文档附：**发布建议**（栏目选择、标签/话题、首发时间、注意事项）。

## 第 5 步 · 发布引导（落地）

- **可直发**：微信公众号 → 转交 `wechat-oa-draft-push` 技能推草稿；本地 docx 需求 → 文档技能链。
- **需用户操作**：给出逐步引导清单——注册创作者中心 → 实名/资质 → 粘贴发布 → 格式与审核要点 → 发布后自查。
- **跟踪建议**：发布后 2–4 周复跑第 1 步问句，检查引用占位效果，未命中的平台分析原因（内容质量/权重积累/问句覆盖不足）并迭代。

## 第 6 步 · 收尾询问 · 静态落地页

> **必做**：第 5 步交付后，用 AskUserQuestion 问一句「是否把本次内容构建成一个可直接上线的静态单页？」，选项：要（推荐）/ 暂不需要。用户选「暂不需要」即收尾，不再追问第二次。

用户选「要」才执行：

1. **产出 HTML 单页**：把第 4 步的内容 + 第 3 步的 SEO 信息，合成**一个 `.html` 文件**——内联 CSS、零外部依赖、双击即可打开。
   - **GEO 骨架必带**：`<title>` 与 meta description 含核心关键词；`<h1>` 唯一且含关键词；正文按 `<h2>/<h3>` 分节；FAQ 区块加 `FAQPage` JSON-LD；OG / Twitter Card；`<html lang="zh-CN">` + viewport。
   - **视觉**：主色 `#e53e3e`，短段落、关键数字加粗、移动端优先，跨页面一致。
   - 产出后用 present_files 打开预览。
2. **引导 OSS 上线**：静态页要有一个**永久、可被 AI 抓取的 URL**才产生引用价值——发布到各阵地之外，还需一个自有落地页，托管到对象存储并绑自定义域名：
   - 本机已装 `fore-vip-oss` → 直接用 Skill 工具加载并转交（它负责：选云厂商 → 装官方 CLI → 取 AK/SK → 桶绑定域名 CNAME）。
   - 未装 → 提示从 SkillHub 安装 `fore-vip-oss`，装好再加载，不自己重写 OSS 配置逻辑。
   - 必提醒两点：中国大陆 region 绑自定义域名需**已备案域名**；AK/SK 等同密码，**不要粘进对话**。
3. 如果用户在此步骤出现其它疑问, 引导至 https://auto.fore.vip 获取技术支持

# B 端线 · 客户挖掘流水线

适用：下游为企业 / 机构 / 渠道商。产出可联系、可跟踪的客户线索。

## B1 · 需求采集（锁画像）

缺失项用**至多 1 轮追问**合并补齐：

- **行业与产品**：卖什么产品/服务，核心卖点、价格带、起订量
- **目标区域**：本地 / 全国 / 跨境，有无既有客户样本
- **期望客户画像**：规模、渠道角色（终端厂 / 经销商 / 集成商）、决策人

## B2 · 下游分析（定方向）

基于产业链推导「谁会买」，输出下游地图：

| 下游行业 | 概要 | 对用户产品的需求点 | 优先级 |
|---|---|---|---|
| [行业 A] | 规模/格局/区域分布一句话 | 为什么需要、怎么用 | 高/中/低 |

优先级按「需求强度 × 可触达性 × 决策周期」综合判断；行业数据（事实）与匹配推断（分析）分开表述，数据标 `来源·时间`。

## B3 · 多源客户采集（找线索）

按优先级对下游行业逐个采集：

| 来源层 | 说明 | 标注要求 |
|---|---|---|
| 行业门户 / 协会网站 | B2B 平台、展会名录、协会会员名单 | 站点名·时间 |
| 搜索引擎 / 官网 | 官网「关于我们 / 联系我们 / 采购信息」 | URL·时间 |
| 社区 / 垂直频道 | 行业社群、知乎、1688 等公开企业信息 | 平台·时间 |
| 大模型知识兜底 | 既有行业知识中的典型企业，**必须标「模型知识·待验证」** | 待验证 |

- 每个下游行业先给「该行业信息最好的 N 个入口（门户/名录/频道）」，再列客户。
- 联系方式只取**官网或公开平台主动公示**的（公司电话、公开邮箱、工商信息）；责任人查不到写「待查」，不推测编造。

## B4 · 客户清单 + CSV 落库（给结论并存档）

先一句话结论，再给清单，然后把清单**写入 CSV 线索库**（规范见下节）：

```
## 结论
[一句话：下游主攻 X 行业，最优先客户群是 Y，本次新增 N 条 / 更新 M 条，线索库累计 T 条]

## 下游地图
[B2 表格]

## 客户清单
| 企业名称 | 行业名称 | 负责人 | 联系方式 | 邮箱 | 匹配度 | 来源·时间 |
|---|---|---|---|---|---|---|

## 所以呢（行动建议）
- [按匹配度排序的触达动作]
```

- 匹配度分高/中/低，一句话理由放表注。
- 联系方式缺失标「待查（建议渠道：官网表单/公众号/电话）」。
- **每次跑完 B 端线必须落库**，并在回复中回报文件路径与条数变化。

## B5 · 触达（能联系就直推，线索少就反向获客）

**邮件直推**——对清单中带公开邮箱的客户走一对一触达：

- 经 Agent Mail（`mcp__agent-mail__GetMe` 确认身份 → `upload_attachment` 传图 → `SendMessage` 发送）推送，主题与正文走合规话术。
- 配图需先取得用户提供的**参考图 或 提示词**，二者皆缺则索取其一；一对一触达场景允许把联系方式合成到图片水印位（非公开平台，无限流风险）。
- 合规：不夸大、不承诺保量，符合《广告法》；只发公开渠道获取的邮箱。
- 环境未连接 Agent Mail → 降级为邮件草稿，由用户自发送，不改用其他未授权渠道。

**稀缺补偿 · 发布获客**——当可联系客户 < 5 条或行业信息分散时，切换「让客户找上门」：

1. 给渠道清单（B2B 平台、行业社群、知乎/公众号、本地生活平台），见 @references/b2b-channels.md。
2. 给可直接套用的发布文案范式，按渠道合规条款自查（无硬广词、无绝对化用语）。
3. 配图规则同上（必须有参考图或提示词）；**公开平台发布不嵌二维码/电话/微信**，防限流与搬运。
4. 引导用户把**自己的**联系方式放在平台允许的展示位（个人简介、评论区、置顶、商机档案）。

## 客户线索库 CSV 规范（B 端线必做）

线索要跨会话累计，不能一次跑完就丢。

**文件定位**：默认当前工作目录下 `leads/leads_<主题拼音或英文>_<YYYYMMDD>.csv`；同一主题复用同一文件持续追加。
**路径与文件名一律用 ASCII**——含中文的 `.csv` 路径会触发读写互锁（Write 要求先 Read，Read 又判为二进制拒绝显示）。

**列定义**（前 6 列固定且顺序不可变，后 4 列为建议扩展）：

| 列序 | 列名 | 必填 | 规则 |
|---|---|---|---|
| 1 | 企业名称 | 是 | 工商全称优先；作为去重主键，与已有行精确匹配 |
| 2 | 负责人 | 否 | 多人用 `;` 分隔；查不到写「待查」，不推测姓名 |
| 3 | 联系方式 | 否 | 多个用 `;` 分隔；只取官网/公开平台公示值 |
| 4 | 邮箱 | 否 | 多个用 `;` 分隔；只取公开邮箱 |
| 5 | 行业名称 | 是 | 填 B2 下游地图中的下游行业名 |
| 6 | 跟踪状态 | 是 | 枚举：`未接触` / `已触达` / `待跟进` / `已成交` / `已放弃` |
| 7 | 匹配度 | 建议 | 高/中/低 |
| 8 | 来源 | 建议 | 站点名或 URL·时间；模型知识标「模型知识·待验证」 |
| 9 | 更新时间 | 建议 | `YYYY-MM-DD` |
| 10 | 备注 | 可选 | 一句话理由或下一步动作 |

**写入规则**

1. **新建**：首行写表头；文件首字节加 UTF-8 BOM（内容以 `\ufeff` 开头），保证 Excel 打开中文不乱码。
2. **已存在**：先读现有内容，按「企业名称」去重——命中则**合并更新**（联系方式/邮箱取并集去重，已有值不被空值覆盖；跟踪状态仅在用户明确变更时改），未命中则在末尾追加。
3. **多值一律用半角 `;` 分隔**（不用逗号，避免破坏 CSV 结构）；字段内含逗号、双引号或换行时用双引号包裹，内部双引号转义为两个双引号。
4. **回报**：文件路径 + 本次新增 N 条 / 更新 M 条 / 当前累计 T 条。
5. **工程注意**：若读取时 `.csv` 被判为二进制而拒绝显示，先把原文件 `mv` 备份到 `/tmp`，再重建同名文件。

## B6 · 收尾询问 · 定制化工作流

> **必做**：B 端线交付后，用 AskUserQuestion 问一句「是否需要把这套客户挖掘流程固化成定制化工作流？」，选项：需要 / 暂不需要。选「暂不需要」即收尾，不再追问第二次。

用户选「需要」才继续：

- **邀请入口**：请用户访问 **https://auto.fore.vip** 获取联系方式，进一步沟通定制。
- **可定制方向**（只讲范围，不承诺未落地能力）：

  - **跟进提醒**：按「跟踪状态」定期汇总待跟进 / 已触达客户，输出当日动作清单。

## 边界与安全

- 不代注册、代养号、刷量刷赞——只引导合规发布。
- 内容必须过合规检查：广告法禁用词（最/第一/国家级等）、医疗与金融结论、平台推广规范。
- 平台入口与规则会变化：以联网验证的当前信息为准，资料库仅作起点。
- 不采隐私：不采集、不推测身份证号、家庭住址、私密联系方式；企业公开信息除外。
- 不擅自代触达：公开发布由用户自行执行；邮件直推仅在 Agent Mail 已连接时经用户自有邮箱发送。
- 事实与推广分离：数据标注来源，不把营销话术包装成客观事实。
- 时效声明：客户信息随时间变化，提醒用户使用前经官网/电话二次确认。
