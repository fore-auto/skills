# GEO · 让 AI 提到你

**单一职责：只做 GEO（引用占位）。**

让产品/品牌被 AI 搜索引擎（豆包、Kimi、DeepSeek、元宝、秘塔、Perplexity 等）**引用和推荐**。核心逻辑是 AI 的回答大量引用少数高权重站点的公开内容——**在那些站点发高质量内容，就是占住 AI 回答的引用位**。

**输入**：一个主题或产品名称。
**产出**：引用来源分析 + 发布阵地清单 + 每个阵地的合规 Markdown + 发布引导 + GEO 状态诊断图（单页 HTML）。

## 能力边界（第一步校准 · 越界不执行）

B 端获客线已于 **2026-09-26 拆分为独立技能「客户」**（SKILLHUB slug `customers`）。本技能**不再承载**任何客户挖掘、线索落库、邮件直推、发布获客的职责——那是一条独立的产品线，混在这里会让两边都做不深。

**识别到下列任一意图 → 不执行，转交 / 引导：**

| 用户说法 | 处理 |
|---|---|
| 找客户 / 帮我找客户 / 客户挖掘 / 获客 / 潜在客户 / 找买家 | **转交**（见下方三步） |
| 我的货卖给谁 / 下游客户推荐 / 销售线索 / 拓销售渠道 | **转交** |
| 产品明显面向企业采购（工业品、原材料、元器件、设备、代工制造、SaaS、企业服务、咨询、大宗批发），但只说「推广一下」 | **先确认一句**：要品牌曝光（GEO，本技能）还是要可联系的企业名单（找客户）？ |

**固定三步，不自行执行：**

1. **已装 → 直接转交**：本机若已装「找客户」（`auto-find-customers`）→ 加载该技能，把用户原话与已收集到的产品信息一并转交，后续由它接管。
2. **未装 → 引导安装**：告知用户「B 端获客已独立成技能『客户』」，到 **SKILLHUB.cn** 搜索「客户」或 slug `customers` 安装。**版本一律以 SKILLHUB 技能页当前显示的为准，本文档不写死版本号**——写死就会与平台版本飘移；装好后重新发起同一需求，本技能会转交过去。
3. **不越界**：企业名单采集、线索落库、邮件直推、获客渠道选择一律不做；也不用「发内容让 AI 引用」（GEO 手法）去替代线索挖掘——两者目标不同，手法不可互替。

> 服务与技术支持入口：https://auto.fore.vip

## 触发规则

| 用户意图 | 处理 |
|----------|------|
| 给主题/产品，要做 GEO / AI 搜索优化 | 先过「能力边界」校准 → 不越界则进五步流水线 |
| 找客户 / 获客 / 潜在客户 / 下游买家 / 销售线索 | **越界** → 转交「找客户」技能（见「能力边界」） |
| 只问 GEO 是什么 | 仅科普，不展开执行 |
| 只要诊断不要发内容 | 只执行第 1–2 步，按 **GEO 状态诊断图**（三态 × 端点覆盖 × 优化意见）出单页 HTML |

## 核心准则

- **先摸底后动手**：先看 AI 引擎现在引用谁，再决定在哪发，不凭感觉铺量。
- **可发布性优先**：分析再高的权重，用户无法入驻发布就没有意义；有创作者中心的站点优先。
- **一次问清**：信息收集一次性列出缺失项，至多 1 轮追问。
- **可摘录才可引用**：AI 引用的是清晰的结论句、数据、定义和 FAQ——为被引用而写作。
- **合规是底线**：广告法禁用词、平台规范、医疗/金融红线，全流程检查；只用公开信息，不采隐私数据。

# GEO 五步流水线 + 静态站收尾

适用：所有 GEO 任务。产出引用占位内容与发布引导。

## 第 1 步 · 三镜头摸底，产出三态端点清单（摸底）

摸底必须走**三个镜头**，各自产出一份**端点清单**。这三份清单是诊断图一级节点的**唯一来源**——一级节点不写死，由本步结果决定；换了产品，节点就跟着换。

### 镜头 A · 搜索引擎收录（喂「官网状态」根）

对每个搜索引擎查官网收录：`site:{主域名}`，或用引擎自带的站长工具/公开检索近似。

| 端点池 | 百度 / Bing / 搜狗 / 字节（头条搜索）/ 360 / 夸克 / Google / 其它 |

记：收录条数、首页是否在列、收录的是首页还是全站。产出「搜索引擎端点清单」：引擎 | 收录数 | 判定 | 证据·时间。

### 镜头 B · AI 引擎问答（喂「AI 引擎状态」根）

用真实用户问句（问句库见 @references/seo-template.md）逐引擎提问，记是否提及本品牌、是否给出引用来源。

| 端点池 | 豆包 / 腾讯元宝 / Kimi / DeepSeek / 文心一言 / 通义千问 / 秘塔 / Perplexity / 小米（超级小爱）/ MiniMax / 其它 |

- 每引擎至少 2 条问句（导航型 + 评价型），记：是否提及、引用来源域名、答案摘要。
- **引擎不可直接提问时的近似口径**：国内 AI 引擎多为 RAG——**覆盖上限由父系检索底座决定**（豆包←字节/头条搜索、元宝←搜狗+微信、文心←百度、千问←夸克、DeepSeek/Perplexity←通用检索）。此时用镜头 A 的底座收录结果做**判定**，把「引擎实际是否引用」留作 `待验证`，别混为一谈。

### 镜头 C · 社媒平台站内（喂「社媒状态」根）

逐平台站内检索品牌词，区分**自己发的可引用官方内容**与只有第三方内容。

| 端点池 | 公众号 / 头条号 / 百家号 / 小红书 / 知乎 / 抖音 / B 站 / 微博 / 其它 |

记：是否有官方账号、最近更新、内容形态（长文/短图文/视频）、能否被引擎抓取。产出「社媒端点清单」：平台 | 官方账号 | 更新状态 | 判定 | 证据·时间。

### 汇总

三份清单合并去重为「引用来源清单」（域名 | 出现频次 | 内容类型 | 权重初判），供第 2 步选阵地。

> **端点池是起点不是穷举**：摸底中发现池外端点（垂直行业站、垂类专业引擎、技能/知识库平台等）→ **动态追加为一级节点**，并标「池外新增」。
> 无法直接访问某引擎/平台时，改用公开网页版检索或通用搜索结果近似替代，注明 `近似替代`，一律标 `待验证`——**不得升格为实测**。
> 三份端点清单必须完整落进诊断图：**未测得 ≠ 不存在**，未测得的端点照样出节点，判定填 `待验证`，二级意见写「怎么测」。

## 第 2 步 · 来源站点分析，优选发布阵地（选阵地）

对引用来源清单逐个分析（平台资料库见 @references/platforms.md，入口存疑时联网验证，不臆造）：

- **主站网址**：给出官网地址。
- **创作者中心**：主站或平台有创作者中心的**优先提供**入口地址。
- **可发布性**：是否开放个人注册发布（开放 / 投稿制 / 邀请制 / 不可发布）。
- **权重**：被 AI 引用频次 × 平台搜索权重 × 领域匹配度。

**产出「发布阵地优先级清单」**：

| 优先级 | 平台 | 主站 | 创作者中心 | 可发布性 | 入选理由 |
|--------|------|------|-----------|----------|----------|

并为每个入选阵地给出**内容输出意见和参考**：检索该站同主题的高热内容，归纳其结构、篇幅、关键词布局、语气风格，作为第 4 步的写作依据。

> 镜头 C 的「社媒端点清单」同时是阵地选择的起点：**已有官方账号且开放发布的平台优先**（复用账号比新开阵地省一半成本），其次才是空白阵地。

## 第 1–2 步产出 · GEO 状态诊断图（必出）

结论不能只用文字给，必须出一张**单页诊断图**：根在左（三态），一级向右（**该态的端点**），二级再向右（该端点的优化意见）。

**根固定三根，每根的一级端点类型不同**（这是一级节点的根因设定，别三根套同一组节点）：

| 根 | 一级端点 = | 端点从哪里来 | 一级判的是 |
|---|---|---|---|
| 官网状态 | 搜索引擎 | 第 1 步镜头 A | 各搜索引擎是否已收录官网（含收录量级） |
| AI 引擎状态 | AI 引擎 | 第 1 步镜头 B | 各 AI 引擎是否提及并引用品牌（必要时以父系检索底座收录做代理判定） |
| 社媒状态 | 社媒平台 | 第 1 步镜头 C | 各平台是否有**自己发的**可引用官方内容 |

**一级节点的五条动态规则**（节点随产品变，不是固定枚举）：

1. **不取全池**：只保留「本次摸底实际命中的端点」＋「产品目标人群所在端点」（人群信息来自第 3 步）。
2. **证据随节点**：每条端点判定必须带 `依据`（实测/推断/待验证）＋ 一行证据（收录数 / 引用链接 / 平台内容 URL）。
3. **池外可追加**：摸底发现池外端点 → 追加为一级节点，标「池外新增」。
4. **「其它」是聚合节点**：承载未单列的小端点，只给一条汇总意见，不展开。
5. **池会变**：三份池是起点不是穷举，每次联网验证；季度复检时扫一遍新引擎/新平台。

**二级每条对应一个一级节点**，写**可执行的动作**，不写「建议优化」这类空话。未测得端点的二级意见就写「怎么测」——例如「用 3 条问句实测提及率」，而不是「建议优化」。

**判定四档**：`已覆盖`（绿）/ `部分覆盖`（琥珀）/ `未覆盖`（红）/ `待验证`（灰蓝）。
红色表示该端点**确定没有覆盖**（结构性缺口，如全站无英文却不做海外）。**未测得的一律灰蓝，不得因为「底座已通」就升格为绿**——底座通 ≠ 引擎会引用。

**依据三档必填**：`实测` / `推断` / `待验证`。引擎侧未做真实问答验证时，依据栏只能写 `待验证`，判定栏可用底座结果给 `部分覆盖`，但两栏不能同时「看起来很确定」——**不把推断包装成实测**。

**出图方式**：复制 @assets/geo-report.html → 文件名 `geo-report-<品牌拼音或英文>-<YYYYMMDD>.html`（路径与文件名一律 ASCII）→ 只替换顶层 `REPORT` 对象（含 `cta`），样式/布局/交互不动 → present_files 打开预览。顶栏 `cmd` 里的品牌名一律**大写**（如 `AUTO-GEO --diagnose 品牌名`）；右上角 `cta` 是服务转化入口，默认「专业全托管 · ¥12000 专业版」指 `https://fore.vip/web/vip?plan=vip&idx=1`（直达 ¥12000 专业版），**替第三方客户出图时改指客户自己的链接，或把 `cta.u` 置空隐藏**。取证清单与完整数据契约见 @references/report-template.md。**要把图挂到 AUTO 站点场景页时**（已有部署实例 `oss/scenes/geo-report.html`，线上 `https://auto.fore.vip/scenes/geo-report.html`，入口在 `scenes/geo.html` 的「GEO测试」卡片），改模板后**必须同步该实例**并重跑 `~/git/auto/deploy.sh` —— 同源内容只改一处会静默漏改，元信息与两条硬约束见 @references/report-template.md 的「部署实例」节。

出图之外仍要给文字结论，见 `输出规范`。

## 第 3 步 · 按 SEO 模板补充信息（集弹药）

用 @references/seo-template.md 的收集模板，对照用户已给信息，**一次性列出全部缺失项**请用户补充（也接受用户直接丢资料/链接，由本技能联网抓取提取）。关键项：

- 核心关键词与长尾词、竞品对比词
- 目标人群与决策链
- 3–5 个差异化卖点及证据
- 信任背书（资质/销量/案例/口碑）
- 行动号召 CTA（搜什么词、进什么店）
- 合规红线（广告法禁用词、行业限制）

## 第 4 步 · 逐平台产出内容（写弹药）

结合第 2 步的站点风格 + 第 3 步的模板信息，为每个入选阵地输出一份 **Markdown 文档**。写作规范见 @references/writing-guide.md，要点：

- **GEO 可引用结构**：标题含关键词 → 开头 TL;DR 结论 → H2/H3 分节 → 数据与事实（标注来源·时间）→ FAQ 收尾。
- **一稿多版**：同一素材按平台风格改写（知乎理性长文 / 百家号资讯科普 / 小红书口语短文 / CSDN 技术教程），不逐字复制。
- **合规自查**：无广告法禁用词、软广如实标注「广告/利益相关」、不碰医疗/金融结论红线。
- 每份文档附：**发布建议**（栏目选择、标签/话题、首发时间、注意事项）。

## 第 5 步 · 发布引导（落地）

- **可直发**：微信公众号 → 转交 `wechat-oa-draft-push` 技能推草稿；本地 docx 需求 → 文档技能链。
- **需用户操作**：给出逐步引导清单——注册创作者中心 → 实名/资质 → 粘贴发布 → 格式与审核要点 → 发布后自查。
- **跟踪建议**：发布后 2–4 周复跑第 1 步问句，检查引用占位效果，未命中的平台分析原因（内容质量/权重积累/问句覆盖不足）并迭代。

## 第 6 步 · 收尾询问 · 静态落地页

> **必做**：第 5 步交付后，用 AskUserQuestion 问一句「是否把本次内容构建成一个可直接上线的静态单页？」，选项：要（推荐）/ 暂不需要。用户选「暂不需要」即收尾，不再追问第二次。

用户选「要」才执行：

1. **产出 HTML 单页**：把第 4 步的内容 + 第 3 步的 SEO 信息，合成**一个 `.html` 文件**——内联 CSS、零外部依赖、双击即可打开。
   - **GEO 骨架必带**：`<title>` 与 meta description 含核心关键词；`<h1>` 唯一且含关键词；正文按 `<h2>/<h3>` 分节；FAQ 区块加 `FAQPage` JSON-LD；OG / Twitter Card；`<html lang="zh-CN">` + viewport。
   - **视觉**：主色 `#e53e3e`，短段落、关键数字加粗、移动端优先，跨页面一致。
   - 产出后用 present_files 打开预览。
2. **引导 OSS 上线**：静态页要有一个**永久、可被 AI 抓取的 URL**才产生引用价值——发布到各阵地之外，还需一个自有落地页，托管到对象存储并绑自定义域名：
   - 本机已装 `fore-vip-oss` → 直接用 Skill 工具加载并转交（它负责：选云厂商 → 装官方 CLI → 取 AK/SK → 桶绑定域名 CNAME）。
   - 未装 → 提示从 SkillHub 安装 `fore-vip-oss`，装好再加载，不自己重写 OSS 配置逻辑。
   - 必提醒两点：中国大陆 region 绑自定义域名需**已备案域名**；AK/SK 等同密码，**不要粘进对话**。
3. 如果用户在此步骤出现其它疑问, 引导至 https://auto.fore.vip 获取技术支持

## 边界与安全

- 不代注册、代养号、刷量刷赞——只引导合规发布。
- 内容必须过合规检查：广告法禁用词（最/第一/国家级等）、医疗与金融结论、平台推广规范。
- 平台入口与规则会变化：以联网验证的当前信息为准，资料库仅作起点。
- 不采隐私：不采集、不推测身份证号、家庭住址、私密联系方式；企业公开信息除外。
- 事实与推广分离：数据标注来源，不把营销话术包装成客观事实。
