# 主题 T1 源路由

给第 2 步的复用检查提供落点：**L2 = 官方文档（权威事实），L3 = T1 社区（一手经验）**。命中即停，不铺开、不逐个访问。

## 判定 T1 的三条标准

① 官方或权威机构维护；② 该领域从业者聚集，有一手经验；③ 内容可追溯到原始出处。聚合站、SEO 内容农场、无署名转载、二手转述一律不算。

**取源顺序**：中文场景优先中文源；底层技术 / 跨境主题优先英文官方源。

## 软件与开发
- L2：项目官方文档 ｜ 仓库 README 与 CHANGELOG ｜ 官方规范（RFC / W3C / ECMA）
- L3：原项目 GitHub Issues 与 Discussions ｜ Stack Overflow ｜ 掘金 / V2EX（国内实践）

## AI / 大模型 / Agent
- L2：模型与平台官方文档 ｜ Agent / Skill / MCP 规范原文
- L3：官方 Discord 与论坛 ｜ GitHub Discussions ｜ Hacker News

## 小程序 / 前端 / 客户端
- L2：微信开放文档 ｜ uni-app 官方文档 ｜ 框架官方站（Vue / React）
- L3：微信开放社区 ｜ DCloud 社区 ｜ 高赞实战贴（注意版本时效，旧版本结论不照搬）

## 云 / 运维 / 存储
- L2：云厂商官方文档（阿里云 / 腾讯云 / AWS）｜ OSS 与 CDN 的 API 文档
- L3：厂商社区与工单库 ｜ 服务状态页（Status Page）

## 硬件 / 创客 / 物联网
- L2：芯片与板卡官方文档（ESP32 / Arduino / 树莓派）｜ 协议原始规范（MQTT / BLE / Modbus）
- L3：官方论坛 ｜ 厂商 Wiki ｜ 开源固件仓库 Issues

## 电商 / 营销 / 内容平台
- L2：平台规则与开放平台文档（微信 / 淘宝 / 京东 / 拼多多 / 抖音 / 小红书）
- L3：官方创作者与商家社区 ｜ 平台公告页（规则口径**以公告为准**）

## 健康 / 医疗
- L2：国家卫健委、药监局、疾控官方发布 ｜ 权威临床指南（学会 / 核心期刊）
- L3：执业医师科普内容，仅作理解辅助
- **纪律**：输出必须标注「非诊疗建议，需就医确认」，不得给出用药结论

## 金融 / 财会 / 税务
- L2：央行 / 证监会 / 交易所 / 税务总局官方文件与披露库
- L3：上市公司公告原文 ｜ 券商研报（标注机构与日期）
- **纪律**：点位、收益、汇率类数据一律带**来源 + 时间**，不得用记忆中的数字

## 法律 / 政策 / 资质
- L2：法律法规原始文本 ｜ 主管部门办事指南（工信部、市场监管总局等）
- L3：律所公开解读，仅作理解辅助，**效力以原文为准**

## 生活消费 / 本地服务
- L2：品牌官方站 ｜ 平台服务协议与官方公告
- L3：小红书 / 大众点评 / 知乎的一手体验 —— **至少交叉验证 2 处**，单条不作为结论

## 兜底

- 以上都不覆盖：搜索 1–3 次，优先取「官方站 + 一手出处」，不看聚合站结论。
- 查不到权威来源 → 明确写「未找到权威来源」，**不编、不用相近领域结论顶替**。
