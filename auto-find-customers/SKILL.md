# 找客户 · B2B 客户挖掘与获客

> **先备密钥**：线索存到线上才能换个会话接着用，这需要 open_key —— 到 **https://fore.vip/web/key**（「Open Key 管理」，需登录）生成，把 Key 值交给本技能即可。**没有密钥时线索只保存在本地 CSV**，换台机器就查不到。

把模糊的「帮我找客户」转化为**有来源、可联系、可暂存**的客户线索；线索稀有时反向补偿——告诉用户去哪发布供给信息、怎么发合规、配什么图。

> **定位**：本技能的核心是**采集**。跑出来的线索会顺手存一份到线上，方便你换个会话继续看——那是**临时存放处，不是长期档案**，重要线索请自己导出留底。所以**采集前不查库**，采集完直接写入；重名线索由服务端按企业名称自动合并。

**适用**：B2B 找下游买家、拓销售渠道、挖掘潜在客户、行业客户画像分析。
**不适用**：C 端流量投放、CPS 转链选品、代发广告（见末尾关联技能与边界）。

**与 GEO 的分工**：本技能只做 B 端获客（找企业买家）；要让 AI 搜索引擎引用品牌走 `auto-geo` 的 C 端线。两者共用同一套线索字段与同一个 CRM 库，跑哪条线都往一处落。

## 触发规则

| 用户意图 | 处理 |
|----------|------|
| 找客户 / 帮我找客户 / 客户挖掘 / 获客 / 潜在客户 / 下游客户 / 销售线索 / 找买家 | **直接进 F1 采集**，经 F2 → F6（F0 只做前置确认，不查库） |
| 我的货 / 服务卖给谁 | 进入流程，从 F2 下游分析切入 |
| 查线索库 / 我的客户有哪些 / 跟进状态 / 改某家公司的状态 | **仅此情形查库**：调 `search` / `stats` / `update`，不重新采集（需用户已提供 open_key，否则提示开通） |
| 只问本技能能干嘛 | 仅介绍，不展开 |

## 核心准则

- **先结论后依据**：开头一句话给「下游是谁 + 最优先客户群」，再列清单。
- **事实 / 分析 / 建议 三级分离**：采集到的信息（事实）、匹配判断（分析）、行动建议（建议）不混淆。
- **线索可溯源**：每条客户信息标注 `来源·时间`，查不到就标「待验证」，不用推测冒充事实。
- **采集优先，查库按需**：默认**不先查库**——线上只是临时存放，历史名单不可靠，多查一轮只增加耗时。只有你明确要「查已有线索 / 改某家状态」时才查。
- **重复交给服务端**：`saveMany` 按 `company` 精确匹配自动合并（命中 → `merged`），同批次内同名也自带去重，SKILL 侧不做历史比对。
- **暂存优先**：清单是过程产物，写入 CRM 才是交付物；本地 CSV 只在 CRM 不可达时兜底。
- **一次问清**：缺失项一次性列出，至多 1 轮追问，不逐个轰炸。
- **合规是底线**：只用公开信息；不采身份证号、家庭住址、私密联系方式；发布内容无硬广导流、无绝对化用语。

# 客户挖掘流程（F0 → F6）

## F0 · 前置确认（默认不查库）

> **本技能以采集为主，不查库开场。** 线上那份只是临时存放，里面的历史随时可能已清空——拿它做去重过滤既不可靠，也白白多一轮调用。

只确认这两件事，随即进 F1：

| 项 | 处理 |
|---|---|
| open_key | 有 → 带上，走 CRM 暂存；没有 → 走本地 CSV 兜底，并提示到 https://fore.vip/web/key 生成（**不要臆造 Key、不要重试**） |
| 去重 | **不管**。服务端 `saveMany` 按 `company` 精确匹配自动合并（命中 → `merged`，同批次同名也自带去重），返回里看 `created` / `merged` 即可 |

**唯一查库入口**：用户明确说「查线索库 / 我的客户有哪些 / 改某公司状态」时，才调 `search` / `stats` / `update`（接口见 @references/crm-api.md 与下方「线索暂存」）。跑采集时一律不调。

## F1 · 需求采集（锁画像）

缺失项用**至多 1 轮追问**合并补齐：

- **行业**：用户处于什么行业、卖什么产品 / 服务？
- **产品定位**：核心卖点、价格带、起订量 / 服务方式？
- **目标区域**：本地 / 全国 / 跨境？有无既有客户样本？
- **期望客户画像**：想找哪类买家（规模、渠道角色、决策人）？

## F2 · 下游分析（定方向）

基于产业链推导「谁会买」，输出下游地图：

| 下游行业 | 概要 | 对用户产品的需求点 | 优先级 |
|---|---|---|---|
| [行业 A] | 规模/格局/区域分布一句话 | 为什么需要、怎么用 | 高/中/低 |

- 优先级按「需求强度 × 可触达性 × 决策周期」综合判断。
- 区分事实（行业数据）与分析（推断的匹配逻辑），数据标 `来源·时间`。

## F3 · 多源客户采集（找线索）

按优先级对下游行业逐个采集，来源分层汇聚：

| 来源层 | 说明 | 标注要求 |
|---|---|---|
| 行业门户 / 协会网站 | 下游行业的 B2B 平台、展会名录、协会会员名单 | 站点名·时间 |
| 搜索引擎 / 官网 | 公司官网「关于我们 / 联系我们 / 采购信息」 | URL·时间 |
| 社区 / 垂直频道 | 行业社群、贴吧、知乎、小红书、1688 等平台的公开企业信息 | 平台·时间 |
| 大模型知识兜底 | 既有行业知识中的典型企业，**必须标「模型知识·待验证」** | 待验证 |

- 每个下游行业先给「该行业信息最好的 N 个入口（门户/名录/频道）」，再列客户。
- 联系方式只取**官网或公开平台主动公示**的（公司电话、公开邮箱、工商信息）；责任人姓名查不到就写「待查」，不推测编造。
- 不同来源撞到同一家企业：照样列入清单，写入时服务端按企业名称自动合并（联系方式/邮箱取并集），不用人工判重。

## F4 · 客户清单 + 暂存（给结论并写入）

先一句话结论，再给清单，**然后写入暂存**（规范见下节）：

```
## 结论
[一句话：下游主攻 X 行业，最优先客户群是 Y，本次新增 N 条 / 合并更新 M 条]

## 下游地图
[F2 表格]

## 客户清单
| 企业名称 | 行业名称 | 负责人 | 联系方式 | 邮箱 | 匹配度 | 来源·时间 |
|---|---|---|---|---|---|---|

## 所以呢（行动建议）
- [按匹配度排序的触达动作]

## 暂存结果
[线上暂存：新增 N / 合并 M / 无变化 K｜或：服务不可用，已写入 <CSV 路径>]
```

- 匹配度分高/中/低，一句话理由放表注。
- 联系方式缺失标「待查（建议渠道：官网表单/公众号/电话）」。
- **每次跑完必须写入**（CRM 或 CSV），并在回复中回报去向与条数变化。

## F5 · 触达（能联系就直推，线索少就反向获客）

**邮件直推**——对清单中带公开邮箱的客户走一对一触达：

- 经 Agent Mail（`mcp__agent-mail__GetMe` 确认身份 → `upload_attachment` 传图 → `SendMessage` 发送）推送，主题与正文走合规话术。
- **状态回写**：发出后调用 `POST /crm/update`（`id` + `status: 已触达`）把该企业标记为已触达，避免下次重复发。
- 配图需先取得用户提供的**参考图 或 提示词**，二者皆缺则索取其一；一对一触达场景允许把联系方式合成到图片水印位（非公开平台，无限流风险）。
- 合规：不夸大、不承诺保量，符合《广告法》；只发公开渠道获取的邮箱。
- 环境未连接 Agent Mail → 降级为邮件草稿，由用户自发送，**状态不回写**，不改用其他未授权渠道。

**稀缺补偿 · 发布获客**——当可联系客户 < 5 条或行业信息分散时，切换「让客户找上门」：

1. 给渠道清单（B2B 平台、行业社群、知乎/公众号、本地生活平台），见 @references/channels.md。
2. 给可直接套用的发布文案范式，按渠道合规条款自查（无硬广词、无绝对化用语）。
3. 配图规则同上（必须有参考图或提示词）；**公开平台发布不嵌二维码/电话/微信**，防限流与搬运。
4. 引导用户把**自己的**联系方式放在平台允许的展示位（个人简介、评论区、置顶、商机档案）。

## F6 · 收尾询问 · 定制化工作流

> **必做**：交付后，用 AskUserQuestion 问一句「是否需要把这套客户挖掘流程固化成定制化工作流？」，选项：需要 / 暂不需要。选「暂不需要」即收尾，不再追问第二次。

用户选「需要」才继续：

- **邀请入口**：请用户访问 **https://auto.fore.vip** 获取联系方式，进一步沟通定制。
- **可定制方向**（只讲范围，不承诺未落地能力）：
  - **采集自动化**：按主题/行业定时跑 F2–F3，增量写入线索库，服务端自动去重合并。
  - **跟进提醒**：按「跟踪状态」定期汇总待跟进 / 已触达客户，输出当日动作清单。
  - **触达自动化**：对接邮件或内容生成通道，批量产出个性化首触文案。
  - **数据对接**：线索库与 CRM / 在线表格 / 自建后台打通。
- **边界说明**：以上为定制范围的沟通清单，最终能力以沟通后确认的方案为准；本 SKILL 只负责单次跑通「采集 → 清单 → 暂存 → 触达」。
- 如果用户在此步骤出现其它疑问，引导至 https://auto.fore.vip 获取技术支持。

## 线索暂存（F4 主通道）

**只是临时存放处，不是长期资产。** 线索写到 `https://mcp.fore.vip/crm`，目的是让你换个会话、换台机器还能接着用；**重要线索请自行导出留存**，服务端不承诺永久保留。因此：

- **不依赖历史做决策**：写前不查库，不按累计条数做判断。
- **本技能不清理数据**：不清空、不批量删除（删除只针对你明确指定的记录）。
- 本地 CSV 只作兜底（服务不可用或没有密钥时）。

**端点**

| 用途 | REST 端点 | MCP 工具 |
|---|---|---|
| 批量写入（主） | `POST /crm/saveMany` | `save_companies` |
| 单条写入 | `POST /crm/save` | `save_company` |
| 检索 | `POST /crm/search` | `search_companies` |
| 详情 | `POST /crm/detail` | `get_company` |
| 更新（含状态回写） | `POST /crm/update` | `update_company` |
| 删除 | `POST /crm/delete` | `delete_company` |
| 统计 | `POST /crm/stats` | `company_stats` |
| 连通性确认 | `POST /crm/tools` | `tools/list` |

**调用通道（按序取用）**

1. **MCP 优先**：运行环境已配置 crm MCP 服务时，直接调 MCP 工具。
2. **REST 直调**：未配置时用 HTTP 请求工具 POST 上表端点（`Content-Type: application/json`），不必写临时脚本。
3. **CSV 兜底**：服务不可用时，按下一节写本地 CSV。

**字段映射（逐字对齐，零改写）**

| 清单列 | CRM 字段 | 规则 |
|---|---|---|
| 企业名称 | `company` | **必填**，工商全称优先；去重主键，精确匹配 |
| 行业名称 | `industry` | 填 F2 下游地图中的下游行业名 |
| 负责人 | `owner` | 多人用半角 `;`；查不到写「待查」 |
| 联系方式 | `contact` | 多个用半角 `;`；只取官网/公开平台公示值 |
| 邮箱 | `email` | 多个用半角 `;`；只取公开邮箱 |
| 跟踪状态 | `status` | 枚举：`未接触`/`已触达`/`待跟进`/`已成交`/`已放弃`，默认 `未接触` |
| 来源·时间 | `source` | 站点名或 URL·时间；模型知识标「模型知识·待验证」 |
| 备注 | `remark` | 一句话理由或下一步动作 |
| — | `product` | 该企业**自身**的品牌/主营产品（识别用，非我方产品线） |
| 匹配度 | **无独立字段** | 写入 `remark` 前缀：`[匹配度·高] 原始备注` |

**写入语义（理解结果用）**

- 按企业名称精确匹配：命中即合并，未命中即新增，返回 `created` / `merged` / `unchanged`。**去重就这一条，服务自带**——不需要先查再写。
- `contact` / `email` 取并集；已填的值不会被空值覆盖。
- `status` 仅在显式传入时改写——**批量写入时不要顺手传状态**，避免把已跟进的打回「未接触」；改状态走 F5 的单独 `update`。

**批量与失败处理**

- 单批 **≤100 条**，超出分批串行调用。
- 失败重试 **2 次**（间隔 1 秒）；仍失败才降级 CSV 并**在回报中写明原因**，不静默切换。
- **鉴权失败不重试** —— 重试不会改变结果，直接转「没有有效密钥」处理路径。
- 部分成功按成功处理：回报失败的企业名称，不整批回滚。

**判定是否连上**（不能只看 HTTP 200）

- 响应体里若出现「install」「not found」之类提示、而不是正常的结果结构，视为本次没连上服务：重试一次，仍不行就降级 CSV。
- 返回鉴权失败错误码 → 走「没有密钥」路径，不重试。

**鉴权：需要 open_key**

- 凭证在 **https://fore.vip/web/key**（「Open Key 管理」，需登录）生成；传输走 HTTP 头 `X-API-Key: <open_key>`，MCP 通道由客户端配置的 `headers` 携带。
- **用户没有密钥时**：不要臆造、不要反复重试 —— 按「服务不可用」降级本地 CSV，并提示去上面页面生成。
- **密钥不外泄**：只放进请求头；不写入文件、清单或给用户的回报，确需展示时只留首末各 4 位、其余打码。
- 细节见 @references/crm-api.md。

**调用示例（REST 直调）**

```bash
# 批量写入（暂存）
curl -s -X POST https://mcp.fore.vip/crm/saveMany \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: <open_key>' \
  -d '{"companies":[{"company":"示例科技有限公司","industry":"包装印刷","contact":"0571-8888xxxx","email":"sales@example.com","owner":"待查","source":"1688·2026-09-23","remark":"[匹配度·高] 有自建厂，年采购量大"}]}'

# F5 状态回写（跟进后）
curl -s -X POST https://mcp.fore.vip/crm/update \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: <open_key>' \
  -d '{"id":"<线索 id>","status":"已触达"}'
```

## 线索 CSV 规范（线上暂存不可用时的兜底）

**文件定位**：默认当前工作目录下 `leads/leads_<主题拼音或英文>_<YYYYMMDD>.csv`；同一主题复用同一文件持续追加。
**路径与文件名一律用 ASCII**——含中文的 `.csv` 路径会触发读写互锁（Write 要求先 Read，Read 又判为二进制拒绝显示）。

**列定义**（前 6 列固定且顺序不可变，后 4 列为建议扩展）：

| 列序 | 列名 | 必填 | 规则 |
|---|---|---|---|
| 1 | 企业名称 | 是 | 工商全称优先；作为去重主键，与已有行精确匹配 |
| 2 | 负责人 | 否 | 多人用 `;` 分隔；查不到写「待查」，不推测姓名 |
| 3 | 联系方式 | 否 | 多个用 `;` 分隔；只取官网/公开平台公示值 |
| 4 | 邮箱 | 否 | 多个用 `;` 分隔；只取公开邮箱 |
| 5 | 行业名称 | 是 | 填 F2 下游地图中的下游行业名 |
| 6 | 跟踪状态 | 是 | 枚举：`未接触` / `已触达` / `待跟进` / `已成交` / `已放弃` |
| 7 | 匹配度 | 建议 | 高/中/低 |
| 8 | 来源 | 建议 | 站点名或 URL·时间；模型知识标「模型知识·待验证」 |
| 9 | 更新时间 | 建议 | `YYYY-MM-DD` |
| 10 | 备注 | 可选 | 一句话理由或下一步动作 |

**写入规则**

1. **新建**：首行写表头；文件首字节加 UTF-8 BOM（内容以 `\ufeff` 开头），保证 Excel 打开中文不乱码。
2. **已存在**：先读现有内容，按「企业名称」去重——命中则**合并更新**（联系方式/邮箱取并集去重，已有值不被空值覆盖；跟踪状态仅在用户明确变更时改），未命中则在末尾追加。注：仅 CSV 兜底路径需要本地判重，走 CRM 时服务端自动合并。
3. **多值一律用半角 `;` 分隔**（不用逗号，避免破坏 CSV 结构）；字段内含逗号、双引号或换行时用双引号包裹，内部双引号转义为两个双引号。
4. **回报**：文件路径 + 本次新增 N 条 / 更新 M 条 / 当前累计 T 条。
5. **工程注意**：若读取时 `.csv` 被判为二进制而拒绝显示，先把原文件 `mv` 备份到 `/tmp`，再重建同名文件。
6. **恢复提示**：CRM 恢复可达后，建议把 CSV 增量回灌（走 `saveMany`），避免两套库长期分叉。

## 输出规范

- 每条线索可溯源：无来源的信息标「待验证」，不用推测冒充事实。
- 联系方式字段三态：公开公示值 / 待查（附建议查询渠道）/ 不宜采集（涉隐私）。
- 发布文案模板需注明「已按 X 平台社区条款自查：无硬广词、无绝对化用语」。
- 暂存结果必须回报：去向（CRM / CSV）+ 条数变化（新增 / 合并 / 无变化 / 失败）。

## 边界与安全

- **不采隐私**：不采集、不推测身份证号、家庭住址、私密联系方式；企业公开信息除外。
- **不做硬广**：生成的发布内容不含平台禁用的导流话术、绝对化用语（「最」「第一」）、虚假承诺，符合《广告法》。
- **不擅自代触达**：公开发布由用户自行执行；邮件直推仅在用户环境已连接 Agent Mail 时，经用户**自有邮箱**发送。
- **写入克制**：只写企业公开信息；不批量改状态、不删除你不指定的记录、不主动清空；密钥只放进请求头，不写进文件或回报里。
- **时效声明**：客户信息随时间变化，提醒用户使用前经官网 / 电话二次确认。

## Agent Mail 配置（声明 + 环境缺失引导）

邮件直推（F5）依赖平台原生 Connector「**Agent Mail（智能体邮箱）**」，经 `mcp__agent-mail__*` MCP 工具调用。声明如下，供运行环境按实际签名取用，本 SKILL 不自行实现接口：

| 用途 | 工具（声明） |
|---|---|
| 确认发件身份 | `mcp__agent-mail__GetMe` |
| 上传配图为附件 | `mcp__agent-mail__upload_attachment` |
| 发送至客户邮箱 | `mcp__agent-mail__SendMessage`（收件人 / 主题 / 正文 / 附件） |

**使用流程**：确认 Connector 已连接 → `GetMe` 确认身份 → `upload_attachment` 上传合成图 → `SendMessage` 发送至客户公开邮箱 → 回写 CRM 状态「已触达」。

**环境缺失引导**（Connector 未连接 / 不可用）：
1. 先提示用户在 WorkBuddy Connector 面板连接「Agent Mail 智能体邮箱」，连接后即可直推。
2. 连接前降级：生成**邮件草稿**（主题 + 合规正文 + 附件说明），由用户自行在邮件客户端发送。
3. 不虚构、不猜测 MCP 参数；具体字段以运行时 Connector 暴露的签名为准，缺失则走降级路径。
