# 实战经验库（field-notes）

> 本文件是技能的**自增长记录**：每一次在真实素材、真实机器上踩到并修好的问题，都在这里留一条。
> 只追加，不改历史条目。发现旧条目过时，新增一条说明并互相引用。

## 记录规则

**写什么**

- 码表命令在真实素材上失败、并被修正过的
- 引擎/工具行为与预期不符（编译开关缺失、参数语义变化、平台规格变更）
- 用户实际报错里出现的、文档没覆盖的症状
- 找到更短路径或更稳定的替代做法

**不写什么**

- 一次性环境故障（磁盘满、网络抖动、机器当时卡死）
- 未经复现的猜测；只写过一次就不再出现的偶发
- 与技能职责无关的失败

**怎么判断该不该写**：这个坑如果明天换一台机器、换一个人来做，还会不会踩？会 → 写。

**写的方式**：用 `scripts/log_note.py` 回写，不要手改本文件。脚本负责编号、查重、递进版本号。

```bash
python3 scripts/log_note.py \
  --symptom "一句话症状（用户视角）" \
  --cause "根因（技术视角）" \
  --fix "修正做法（可复制的命令或规则）" \
  --verify "怎么确认修好了" \
  --scope "影响哪些操作"
```

**查阅时机**：第 0 步环境探测之后、以及任何命令报错时，先在本文件里搜症状关键词，再决定要不要动手排查。

## FN-001 · 在 zsh 里粘贴含 `0:a?` 的命令，报 `no matches found` 且什么都没生成

- **记录日期**：2026-09-28
- **环境**：macOS 15.8 / zsh 5.x / ffmpeg 9.0.1
- **症状**：命令里有 `-map 0:a?` 这类带问号的参数时，zsh 直接报 `zsh: no matches found: 0:a?`，命令根本没执行。
- **根因**：zsh 默认对未匹配的 glob 报错（bash 默认原样传递）。`?` 是单字符通配符，本机没有名为 `0:a?` 的文件，于是展开失败。
- **修正做法**：含 `?` 的参数一律加引号 —— `-map "0:a?"`。本技能的 `probe_media.py --run` 走参数列表直接传给进程，不经过 shell，天然规避此问题，**优先用 `--run`**。
- **验证**：同一命令改为 `-map "0:a?"` 后执行成功，输出文件正常生成。
- **影响面**：所有涉及可选音轨/字幕轨映射的命令（压缩、竖屏、平台规格输出等）。

## FN-002 · 两条不同规格的素材做转场，命令不报错但输出文件是空的

- **记录日期**：2026-09-28
- **环境**：ffmpeg 9.0.1，输入为 1920×1080 与 1080×1920 各一段
- **症状**：`xfade` 返回码为 0，输出文件存在但 0 字节；日志里是 `streams received no packets`。
- **根因**：`xfade` 要求两路输入的分辨率、像素格式、帧率、SAR 完全一致，不一致时滤镜图静默产不出帧。
- **修正做法**：先统一规格再接转场。

  ```
  [0:v]scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=30[v0]
  [1:v]scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=30[v1]
  [v0][v1]xfade=transition=fade:duration=1:offset=7[v]
  ```

- **验证**：输出 1920×1080、12 秒，与预期时长一致（7 秒 + 5 秒 − 1 秒转场）。
- **影响面**：所有转场、叠加、拼接类滤镜。**通用教训：滤镜报 0 字节输出时，先查输入规格是否对齐。**

## FN-003 · Linux 上 `apt install ffmpeg` 能装，`dnf install ffmpeg` 装不上

- **记录日期**：2026-09-28
- **环境**：Fedora 系发行版
- **症状**：`sudo dnf install ffmpeg` 报找不到包。
- **根因**：Fedora 官方源里的包名是 `ffmpeg-free`，且精简版不含 H.264/H.265 编码器；完整编码器需启用 RPM Fusion 后装 `ffmpeg`。
- **修正做法**：Fedora 优先 `sudo dnf install -y ffmpeg-free`（够用）；要完整编码器再启用 RPM Fusion。各系统包名对照见 `references/install-matrix.md`。
- **验证**：安装后 `ffmpeg -version` 有输出，且 `-encoders` 里能看到 `libx264`。
- **影响面**：Linux 引导安装话术与 `detect_env.py` 输出的安装计划。

## FN-004 · 抽完字幕，报告说「体积减少 100%」

- **记录日期**：2026-09-28
- **环境**：本技能 `probe_media.py`，源为 6MB 的 mkv，输出为几 KB 的 srt
- **症状**：提取字幕成功后，脚本汇报「体积：6.0MB → 0.0MB（-100%）」，对用户毫无意义且容易被理解成「文件被清空了」。
- **根因**：体积对比逻辑对所有输出无差别生效，没区分「音视频容器之间」与「音视频 → 文本/图片」。
- **修正做法**：新增 `MEDIA_OUT_EXTS` 白名单，只有输出扩展名在音视频容器集合内才比较体积；抽字幕、抽帧、转 GIF 一律跳过体积汇报，只报产物路径。
- **验证**：提取字幕不再出现体积行；压缩任务仍正常报出体积变化。
- **影响面**：抽字幕、抽帧做封面、转 GIF、导出音频以外的所有非音视频产物。

## FN-005 · 打包或首次运行后，产物里混进了 `__pycache__`

- **记录日期**：2026-09-28
- **症状**：脚本跑过一次再打包，压缩包里出现 `scripts/__pycache__/*.pyc`。
- **根因**：Python 导入或直接执行都会在脚本同目录生成字节码缓存，打包工具不会自动排除。
- **修正做法**：打包前先清 —— `find "<技能目录>" -name "__pycache__" -type d -exec rm -rf {} +`。技能目录内**不要**保留任何生成物。
- **验证**：`find` 结果里只剩源码与文档。
- **影响面**：所有交付与分发动作（压缩、镜像、上传）。

## FN-006 · 检测工具是否安装，结果全部误判成「已安装」

- **记录日期**：2026-09-28
- **环境**：zsh
- **症状**：检测脚本报告一堆根本没装的工具「已安装」。
- **根因**：`p=$(which xxx)` 在找不到命令时，zsh 会把 `xxx not found` 打到 **stdout**，变量非空，于是 `[ -n "$p" ]` 恒为真。
- **修正做法**：判断命令是否存在一律用 `command -v`，不要用 `which`，也不要只看 `[ -n "$p" ]`。
- **验证**：未安装的工具在探测报告里正确显示为缺失。
- **影响面**：`detect_env.py` 的检测逻辑，以及任何写给用户复制粘贴的工具检测片段。

## FN-007 · 纯音频文件被当成正常视频汇报

- **记录日期**：2026-09-28
- **症状**：把一个 mp3 丢进去，报告里能读出「时长、体积、声音」，看起来像视频，但后续所有画面类操作都会失败。
- **根因**：探测逻辑只要拿到 streams 就照常输出，没有对「缺少视频流」这一情况单独提示。
- **修正做法**：无视频流时明确写「不含画面轨道（纯音频文件），只能做音频处理」，并抑制画面相关字段；无有效流时直接报错。
- **验证**：mp3 → 报告明确说明只能做音频处理；正常视频回归无异常。
- **影响面**：所有素材探测报告与后续菜单生成。
